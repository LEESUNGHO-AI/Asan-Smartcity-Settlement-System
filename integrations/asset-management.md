# 자산관리 시스템 연동

별도로 운영 중인 자산관리 시스템을 중요재산(R-06)의 원천으로 삼는다.
중복 입력하지 않는다.

## 시스템 관계

```
Slack #자산관리대장
      ↓
Notion 자산관리 마스터 DB (2aa50aa9577d81ee9cd0e7e63b3fdf25)
  · 자산 85개 · 총 152억 · 자산등급/구매금액/취득일/설치위치
      ↓  ① 자산관리 시스템 자체 대시보드
      │     https://leesungho-ai.github.io/Asan-asset-management/
      │
      ↓  ② 취득가액 50만원 초과분 → 정산 중요재산
Notion 중요재산 DB (3cd50aa9577d810fa829db49e4ef532f)
      ↓  매일 07:00 sync-notion.js
data/assets.json
      ↓
정산 대시보드 · 법정 중요재산 보고
```

## 왜 두 DB 로 나누는가

- **자산관리 마스터 DB** = 전체 자산 대장 (85개). 라이프사이클·점검·QR·담당자 등
  운영 관점의 모든 자산을 관리한다.
- **중요재산 DB** = 그중 보조금법 §35 적용 대상 (취득가액 50만원 초과).
  처분제한기간·취득보고일·부기등기 등 정산·감사 관점의 항목을 추가로 관리한다.

같은 자산이라도 두 DB 의 관점이 다르므로 분리하되, 자산관리 DB 를 원천으로 하여
중요재산 DB 를 채운다. 자산관리 시스템에서 취득가액·취득일이 확정되면
중요재산 DB 에 반영한다.

## 매핑 규칙

| 자산관리 DB | → | 중요재산 DB |
|---|---|---|
| 자산명 | → | 재산명 |
| 모델명 | → | 규격 |
| 구매금액 | → | 취득가액 |
| 구매일자 | → | 취득일 |
| 설치위치 | → | 설치장소 |
| (자산분류 무관) | → | 재산구분 = 기계·장비 (부동산 아님) |
| (자동) | → | 처분제한기간 = 5년 (기계·장비, 지침 §46③) |

부동산이 생기면 처분제한 10년 + 부기등기 필요로 별도 처리한다.
현재 이 사업의 중요재산은 전부 기계·장비이다.

## 취득보고 (R-06)

중요재산은 취득 후 15일 이내 보고 의무(지침 §46①). 취득일이 2026-07-31 인
SDDC 계열은 보고기한이 지났으므로 **소급 보고**가 필요하다. 대시보드가
취득보고일 미기재 건을 R-06 으로 표시한다.
