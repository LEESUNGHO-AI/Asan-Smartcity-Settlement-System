# 정산 원장 운영 매뉴얼

## 원장의 위치

```
Slack (#정산-증빙)  →  Notion DB  →  data/*.json  →  보고서·대시보드
   입력 채널           검토 화면       ★정본★         산출물
```

값이 충돌하면 **언제나 `data/*.json`이 우선**한다. Notion과 GitHub이 다르면
GitHub이 맞다고 보고 Notion을 고친다. 반대로 하지 않는다.

---

## 파일별 역할

| 파일 | 무엇을 담는가 | 누가 고치는가 |
|---|---|---|
| `data/baseline.json` | 협약·교부결정·법정 임계값·미확정사항 | PMO 총괄만 |
| `data/budget.json` | 비목·세목별 예산집행계획(A) | PMO 총괄만 |
| `data/evidence.json` | 지출 1건 = 1레코드 | 정산 담당 |
| `data/contracts.json` | 계약 1건 = 1레코드 | 계약 담당 |
| `data/assets.json` | 중요재산 1건 = 1레코드 | 자산 담당 |
| `data/completion.json` | 단위사업별 준공서류 확보 현황 | 준공 담당 |

`baseline.json`과 `budget.json`은 **협약·변경승인 문서가 있을 때만** 고친다.
증빙을 맞추려고 예산을 고치는 순간 원장이 무의미해진다.

---

## 월간 사이클

### 1주차 — 수집
전월 지출건을 `evidence.json`에 추가한다. `검토상태`는 `제출완료`로 시작한다.

```bash
npm run validate     # 결손·위반 즉시 확인
```

### 2주차 — 보완
R-02(지급방식), R-05(증빙 결손), R-08(인건비 요건) 오류를 해소한다.
해소가 불가능한 건은 `검토상태: 보완필요` + `보완사유`를 기재하고 남긴다.
**삭제하지 않는다.** 감사에서 "이 건은 왜 빠졌나"에 답해야 한다.

### 3주차 — 확정
검토가 끝난 건을 `검토상태: 확정`으로 전환한다. 확정 건만 보고서에 반영된다.

### 4주차 — 산출
```bash
npm run report -- --from 2026-07-01 --to 2026-07-31 --org JEIL
```
`output/`에 집행결과 제출 양식 DOCX가 생성된다. 이 폴더는 커밋하지 않는다.

## 증빙 1건 추가하기

```jsonc
{
  "증빙ID": "EV-2026-00040",          // 연번 이어서. 재사용 금지
  "기관": "JEIL",
  "단위사업": "SP-NET",
  "보조비목": "건설비", "비목코드": "420",
  "보조세목": "시설비", "세목코드": "03",
  "재원": "국비",
  "계약ID": "CT-2026-0002",
  "지급처": { "구분": "사업자", "명칭": "주식회사 싸인텔레콤", "사업자등록번호": "114-81-82595" },
  "집행일자": "2026-07-15",
  "집행금액": 207525000,
  "사용목적": "유무선 네트워크 구축 용역 1차 기성",   // 사업 관련성이 드러나게
  "지급방식": "계좌이체",
  "증빙유형": ["계약서", "기성검사조서", "전자세금계산서", "계좌이체증"],
  "검토상태": "제출완료",
  "감사추적": { "등록일시": "2026-07-20T09:00:00Z", "등록자": "김주용", "출처": "Notion" }
}
```

**개인 지급건**(인건비·여비·평가위원 수당)은 `지급처`를 다음과 같이 쓴다.

```jsonc
"지급처": { "구분": "개인", "명칭": "이성호", "생년월일": "'76.05.**", "참여율": 90 }
```

생년월일의 일(日) 자리는 반드시 `**`. R-21이 막는다.

## 커밋 메시지 규약

커밋 메시지가 곧 변경 사유이고, 감사에서 증거가 된다.

```
data(evidence): EV-2026-00040 추가 — SP-NET 1차 기성 207,525,000원
data(baseline): 사업기간 종료일 확정 (국토부 회신 2026-09-03, 문서번호 도시경제과-1234)
data(budget): 건설비/시설비 예산 조정 (변경승인 제2026-3호)
fix(rules): R-22 세목 초과집행 판정 누락 수정
docs(rules): R-20 선금 정산 규칙 근거 보완
```

금지: `update`, `수정`, `데이터 반영` 같은 무의미한 메시지.

## 검증 오류 대응

| 규칙 | 나오면 해야 할 일 |
|---|---|
| R-01 | 협약서·교부결정통지서를 확인해 `confirmed: true`로 전환. **추정치를 확정으로 표기 금지** |
| R-02 | 개인카드·현금 지출건 — 자부담으로 대체하거나 불인정 처리 |
| R-03 | 계약서 e나라도움 등록 지연 — 지연 사유서 작성 |
| R-06 | 중요재산 미등재 — `assets.json`에 추가하고 15일 내 보고 |
| R-08d | 참여율 100% 초과 — 참여율 정정 후 인건비 재계산 |
| R-11 | 낙찰차액 — 변경승인 신청 또는 반납 계획 수립 |
| R-20 | 선금 — 기성·준공 정산 진행 및 선금보증증권 회수 확인 |
| R-21 | 생년월일 마스킹 — 즉시 수정. 이미 push했다면 SECURITY.md 7항 |
| R-22 | 예산 초과집행 — 변경승인 없이는 전액 불인정 |

## 릴리스

정산 제출·검증 등 확정 시점마다 태그를 남긴다. 태그 시점의 원장을 언제든 복원할 수 있어야 한다.

```bash
git tag -a v2026.06-집행결과제출 -m "2026년 상반기 집행결과 제출본"
git push origin --tags
```
