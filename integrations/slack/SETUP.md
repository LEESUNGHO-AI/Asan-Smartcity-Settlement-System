# Slack 구성

## 채널

| 채널 | 용도 | 비고 |
|---|---|---|
| `#정산-증빙` | 증빙 등록 (Workflow 폼) | 신규 개설 |
| `#정산-알림` | 검증 결과 자동 알림 | 신규 개설, 봇 전용 |

`#정산-알림`은 봇만 쓰기 가능하도록 설정한다. 사람이 끼어들면 알림이 묻힌다.

## 왜 Workflow 폼인가

자유 텍스트를 파싱하지 않는다. `"11월 회의비 8만원 카드"` 같은 메시지는
비목·세목·재원·지급방식을 추론해야 하고, 추론은 반드시 틀린다.
정산 데이터에서 한 건의 오분류는 총괄명세서 전체를 어긋나게 한다.

**폼은 선택지를 강제한다.** 이것이 R-22b(예산 외 비목 집행)를 입력 단계에서 막는 방법이다.

## Workflow 설계 — "정산증빙 등록"

Slack → 도구 → 워크플로 빌더 → 새 워크플로

### 1단계: 시작
- 트리거: **링크에서 시작** (채널 `#정산-증빙`에 고정)

## 증빙 파일 취급

**Slack에 파일을 올리지 않는다.** Slack 파일은 보존 정책에 따라 삭제될 수 있고,
2031년까지 보관해야 하는 정산 증빙의 저장소로 부적합하다.

원본은 Google Drive의 연도/기관/비목 폴더에 두고, 공유 링크만 `파일링크`에 넣는다.

```
아산_강소형_정산증빙/
  2026/
    JEIL/
      건설비/
      인건비/
```

## 알림 (GitHub → Slack)

Slack 앱 → Incoming Webhooks → `#정산-알림` 대상 웹훅 생성 →
URL을 GitHub Secrets의 `SLACK_WEBHOOK_URL`에 등록.

매일 07:00 KST에 동기화·검증이 돌고 결과가 이 채널로 온다.
오류가 0건이면 조용하고, 있으면 규칙별로 요약해 알린다.

## 설치 확인

1. Apps Script에서 `testConnection()` 실행 → 필수 속성 존재 확인
2. Workflow를 한 번 실행해 Notion에 페이지가 생기는지 확인
3. 지급방식을 `개인카드`로 넣어보고 반려 메시지가 스레드에 오는지 확인
4. 생년월일에 `'82.05.10`을 넣어보고 Notion에 `'82.05.**`로 저장되는지 확인
