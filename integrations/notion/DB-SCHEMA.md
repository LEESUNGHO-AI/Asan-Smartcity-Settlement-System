# Notion DB 속성 정의

## DB는 손으로 만들지 않는다

속성 30개를 화면에서 만들면 오타가 난다. 오타 하나로 `sync-notion.js`가 필드를 찾지 못하고,
그 필드는 **조용히 비어서** 정산에 반영된다. 스키마에서 자동 생성한다.

```bash
node integrations/notion/setup-databases.js --dry-run     # 정의 미리보기 (토큰 불필요)
node integrations/notion/setup-databases.js               # 4종 전부 생성
node integrations/notion/setup-databases.js --db evidence # 정산증빙만
node integrations/notion/setup-databases.js --db evidence --update   # 기존 DB에 누락 속성 보강
```

필요한 환경변수는 `NOTION_TOKEN`과 `NOTION_PARENT_PAGE`(DB를 만들 상위 페이지 ID)다.
실행이 끝나면 GitHub Secrets에 넣을 DB ID가 출력된다.

`--update`는 누락 속성 추가와 **선택지 보강**을 함께 수행한다.
`codes/*.json`에 비목이나 단위사업을 추가한 뒤 이 명령을 돌리면 Notion 드롭다운이 따라온다.
기존 속성을 삭제하거나 이름을 바꾸지는 않는다 — 데이터가 딸려 사라지기 때문이다.

| DB | 속성 | 동기화 |
|---|---|---|
| 정산증빙 DB | 30개 | `scripts/sync-notion.js` ✔ |
| 계약대장 DB | 25개 | 미구현 |
| 중요재산 DB | 25개 | 미구현 |
| 준공산출물 DB | 22개 | 미구현 |

> **Notion API는 뷰(View)를 만들 수 없다.** 아래 "뷰 구성"은 DB 생성 후 화면에서 직접 만든다.

## 정산증빙 DB — 속성 상세

`data/evidence.json`의 스키마와 1:1로 대응한다. 속성명을 바꾸면 `scripts/sync-notion.js`가
필드를 찾지 못하므로, 변경 시 반드시 스크립트의 `MAP` 상수를 함께 수정한다.

## 선택 옵션값

스키마 열거값과 어긋나면 동기화가 실패한다. 아래 값만 등록한다.

```
기관        ASAN, JEIL, HOSEO, CNI, KAIST
단위사업     SP-OASIS, SP-INNO, SP-POLE, SP-STORE, SP-NET, SP-DRT, SP-AI, SP-RND, SP-PMO
보조비목     인건비, 운영비, 여비, 업무추진비, 직무수행경비, 연구개발비,
            민간이전, 자치단체이전, 건설비, 유형자산, 무형자산, 보전금
재원        국비, 도비, 시비, 자기부담금
지급방식     계좌이체, 보조금전용카드, 현금, 개인카드, 법인카드, 기타
검토상태     미제출, 제출완료, 검토중, 보완필요, 확정, 불인정
```

`보조세목`은 `codes/expense-categories.json`을 따른다.
**비목코드·세목코드는 Notion에 두지 않는다.** 동기화 시 코드 마스터에서 자동으로 붙인다.
사람이 입력하면 틀리기 때문이다.

## 뷰 구성

| 뷰 | 필터 | 용도 |
|---|---|---|
| 보완필요 | 검토상태 = 보완필요 | 담당자 작업 목록 |
| 미확정 | 검토상태 ≠ 확정 | 정산 반영 대기 |
| 이번달 | 집행일자 = 이번 달 | 월간 마감 |
| 기관별 | 기관으로 그룹화 | 컨소시엄 진척 |
| 비목별 | 보조비목으로 그룹화, 집행금액 합계 | 총괄명세서 대조 |

## 통합 연결

Notion → 우측 상단 `···` → 연결 → 내부 통합을 추가한다.
통합에 필요한 권한은 **콘텐츠 읽기 + 콘텐츠 업데이트**(증빙ID 되쓰기용)까지이며,
삽입 권한은 GAS가 사용한다.
